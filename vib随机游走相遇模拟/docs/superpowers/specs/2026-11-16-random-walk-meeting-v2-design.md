# 随机游走相遇模拟第2版设计规格

## 目标

以 `随机游走相遇模拟第1版.html` 为唯一原始依据，新增一个单文件、离线可运行、无外部依赖的优化版本。新版保留原有玩法，同时整理代码结构，并采用克制的深色实验仪器风提升界面体验。

原文件必须保持不变，现有 `随机游走相遇模拟.html` 和 `随机游走相遇模拟-优化版.html` 也不修改。

## 交付物

- 新增 `随机游走相遇模拟第2版.html`。
- 新增本设计规格文档。
- 不引入构建工具、包管理器依赖、外部字体、图片、CDN 或网络请求。

## 功能范围

新版完整保留第1版的以下行为：

- 甲、乙从原点出发。
- 每次操作让两人各自向上、下、左、右随机移动一格。
- 空格键和“走一步”按钮均触发一步。
- “自动”按钮开始连续移动，再次点击后暂停。
- “重置”按钮清空轨迹、统计和视图状态。
- 轨迹持续保留，并在视图边界变化时自动缩放。
- 显示步数、当前直线距离、相遇次数和最近一次相遇步数。
- 当两人走完一步后位于同一格时，判定为一次相遇。

以下行为明确不属于本次范围：

- 不增加交叉穿行判定。
- 不增加历史记录列表、速度调节、种子输入或统计图表。
- 不改变随机游走规则，也不引入新的模拟模式。

## 代码结构

代码继续保持单个 HTML 文件。内联 JavaScript 按职责组织为以下部分：

1. 配置与 DOM 引用。
2. 模拟状态与纯逻辑函数。
3. Canvas 坐标计算与绘制。
4. UI 更新、动画循环和事件绑定。

模拟状态统一维护甲、乙轨迹、当前步数、相遇次数、最近相遇步数、坐标边界和相遇动画状态。单步逻辑负责生成新位置、更新边界、检测相遇和刷新 UI；绘制逻辑只读取状态，不修改模拟结果。

重置必须清理所有轨迹、统计、边界、相遇动画和自动播放状态。动画循环避免重复注册，并在不需要持续绘制时停止。

## 界面设计

视觉采用深色实验仪器风：

- 背景为近黑蓝，配合低对比方格网。
- 甲轨迹使用蓝色，乙轨迹使用橙色。
- 不使用紫蓝渐变按钮、玻璃拟态、装饰性光斑或发光点。
- 甲、乙的当前位置采用不同标记形状，配合图例，在颜色之外提供区分。
- 统计数字使用等宽数字样式，增强仪表读数感。

面板保持信息紧凑，包含标题、简短说明、单步主按钮、自动与重置按钮、四项统计和图例。相遇提示使用独立状态区域，不挤压统计布局。

## 响应式与可访问性

- 桌面端面板位于左上角，Canvas 模拟区域在面板之外的剩余空间中居中。
- 窄屏端面板固定在底部安全区域，统计变为两列，控制按钮保持适合触控的尺寸。
- 相遇提示在移动端位于面板上方，不遮挡按钮。
- 按钮具备清晰的 hover、active 和键盘 focus 状态。
- 自动按钮通过 `aria-pressed` 反映播放状态。
- 相遇提示使用状态语义，供辅助技术读取。
- 系统启用 `prefers-reduced-motion` 时关闭相遇脉冲动画，但保留功能与提示。

## 错误处理与健壮性

- Canvas 上下文创建失败时，页面显示可读错误提示，不抛出未处理异常。
- 自动播放暂停后不得继续增加步数。
- 连续快速点击自动按钮不得创建多条独立动画循环。
- 重置后首次绘制必须立即显示原点状态。
- 页面尺寸变化时重新计算 DPR、Canvas 尺寸、面板占用区域和模拟居中区域。

## 验证标准

实现完成后验证以下内容：

1. 原第1版及另外两份现有 HTML 的字节内容未发生变化。
2. 新文件以 UTF-8 保存，中文标题、说明、控件和提示均正常显示。
3. 页面离线打开时无外部网络请求或缺失资源。
4. 初始状态为步数 0、距离 0.0、相遇次数 0、最近相遇为空。
5. 每次单步只增加一步，两人各移动一个曼哈顿单位。
6. 自动播放会增加步数，暂停后步数保持不变。
7. 重置后轨迹、统计、相遇提示和视图边界恢复初始状态。
8. 使用可控随机序列验证“两人回到同一格”会准确增加相遇次数。
9. 桌面和手机视口中，面板、提示、按钮、统计和 Canvas 内容互不遮挡。
10. Canvas 在初始、单步后和重置后均产生非空可见绘制。

浏览器自动化用于交互与布局验证；源码检查用于确认单文件、无外部依赖和原始文件未被修改。
